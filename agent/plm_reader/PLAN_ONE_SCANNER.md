## 0. ЦЕЛЕВОЕ СОСТОЯНИЕ (что должно быть в итоге)

```
ФАЙЛ (Z:)  ──① read (ОДИН раз, RAM)──►  байты
                                           │
                                           │ ② разбор = ящики (ОДИН проход)
                                           ▼
                                     ЕДИНАЯ БАЗА (черновик → публикация)
                                           │
        ┌──────────────────────────────────┼──────────────────────────────┐
        ▼                                  ▼                              ▼
  CONNECTION BUILDER                 GRAPH BUILDER                     ПОКАЗ
  (читает БАЗУ)                      (читает БАЗУ)              (окно/HTML, читает БАЗУ)
  пишет links/derived/props          пишет graph_*              НИЧЕГО не пишет
```

**Четыре инварианта (проверяемые счётчиком):**

| # | Инвариант | Как проверить (команда) |
|---|---|---|
| 1 | Файлы Creo читает РОВНО ОДИН модуль (`engine.py`) | `Select-String 'open(.*rb'` по корню → только engine.py (+creo_read как библиотека) |
| 2 | Сканер читает файл ОДИН раз за проход | в `do_scan` один `scan_item_new`; второго вызова нет |
| 3 | Сканер пишет ВСЕ таблицы своей группы | таблицы `snapshots/params/links/derived/…` не пусты после скана |
| 4 | Прочие модули НЕ читают `Z:` | `Select-String 'FROM links\|FROM derived'` вне построителя = пусто |

## 3. ГРАНИЦЫ И ЗАПРЕТЫ

- 🚩 **Полный скан склада — НЕ агент.** Боевая база живёт на шаре `Z:`, а шару агенты не трогают
  ни в каком виде (§82). Полный скан и публикацию делает ВЛАДЕЛЕЦ. Агент проверяет на локальной
  копии/черновике (`%TEMP%`), в чужую базу не пишет.
- ❌ Двух входов скана быть не должно (§96.3.1: вход ОДИН — `engine.scan_to_base`).
- ❌ Новых настроек под сканер не плодить — только существующие галочки (§96.3.2).
- ❌ Правка `SCHEMA` — не терять `CREATE TABLE` (§96.3.4, живой провал V140).
- ❌ Связи строит ТОЛЬКО `plm_build_links` / показывает `plm_graph.plm_edges()` (§85.4).
- ❌ Правило 7 README: новый канал = функция в сканере, НЕ отдельный скрипт в корне.

## 4. ПОРЯДОК ОЧЕРЕДНОСТИ (почему именно так)

1. **Запись (ЭТАП 1) — первой.** Иначе переключение прохода **потеряет** данные (пустые таблицы).
2. **Адаптер (ЭТАП 2) — вторым.** Иначе новый сканер не отдаст паспорт/параметры/состав.
3. **Один проход (ЭТАП 3) — только после 1 и 2.** Тогда переключение безопасно.
4. **Флаги (ЭТАП 4) и файлы (ЭТАП 5) — после.** Чистка следует за работой, не опережает.
5. **Приёмка (ЭТАП 6) — на СЕТЕ.** Склад — слово владельца.
