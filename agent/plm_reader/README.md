# PLM Reader V16 — читаем изделия «в лоб» (без Creo)

Автономная программа дома: читает файлы Creo (`.prt/.asm/.drw`) **напрямую**, собирает **свою базу**
(паспорта, состав, входимость, изменения, заготовки/отливки, модельная оснастка) и показывает всё
в одном окне: таблица + дерево производства.

- Файлы **не изменяются** — только чтение. Никакие данные никуда не отправляются.
- **База одна** и своя — в подпапке `plm_reader\db\` (в гит не идёт, при передаче пропускается).
  Каждый скан публикуется **новым файлом** `plm_reader_ГГГГММДД_ЧЧММСС.db`; читатели берут **свежайший**.
- **Внешних библиотек не нужно — всё на стандартной библиотеке Python.** На машине нужен только
  **Python 3.11+ с tkinter** (tkinter входит в стандартную установку) — больше доустанавливать нечего.
- **Переносимость:** папку можно скопировать целиком на другой ПК (Windows) — читатель `creo_read.py`
  вложен внутрь, перенос ПУРГЕ встроен; внешних инструментов ПЛМ не требует.

## Быстрый старт

1. Двойной щелчок по **`plm_reader_gui.bat`** — открывается окно.
2. Строка **«Папка»** — корень склада (по умолчанию `Z:\PTC`), кнопка **«Выбрать…»**.
3. **`Сканировать`** — первый раз прочитает файлы и наполнит базу; дальше **повторный скан секунды**
   (читается только изменившееся, журнал пополняется сам).
4. Смотри: вкладка **`Таблица`** — список; внизу — **дерево производства выбранного изделия**;
   вкладка **`Дерево`** — все верхние сборки со входимыми изделиями.

## Окно: порядок сверху вниз

| Где | Что внутри |
|---|---|
| **1. самый верх — настройки** | строка 1: `Папка: [поле] [Выбрать…] Пропускать > МБ: [поле] [с подпапками] [только последние версии]`; строка 2: `Глубина папок (0=все): [поле] ПУРГЕ: оставить версий: [поле] [автообновление]` |
| **2. ниже — инструменты** | `Сканировать · Стоп · Актуально? · README · Выгрузить в CSV · Столбцы и параметры… · История выбранного · История по папке` |
| **3. окно** | вкладки `Таблица` / `Дерево` / `Проводник` (таблица + нижнее дерево производства / дерево ПЛМ целиком / иерархия папок склада) |
| **4. самый низ — данные** | статус и вердикт: `база: файлов N · моделей M · изменений K`, прогресс скана, `БАЗА АКТУАЛЬНА` / `НУЖЕН СКАН: новых N · изменённых M`; строку можно **скопировать** (кнопка «Копировать» / ПКМ) |

## Вкладка «Таблица» (список + дерево снизу)

- Таблица: `Файл · Обозначение · Наименование · Материал · Объём, мм³ · Роль · Родитель · Ревизия ·
  Записей · Дата · Создан · Изменён · Пользователь · Версия Creo` (набор столбцов меняется кнопкой `Столбцы и параметры…`).
  Где `Дата` — последнее изменение по истории Creo; `Создан`/`Изменён` — даты **файла** (ОС), заполнены всегда.
- **Фильтр** — по **всем словам сразу**: каждое слово ищется в любой колонке (напр. `Корпус CHUGUN_VCH50`
  → 50 строк). Поиск запускается после паузы в наборе (дебаунс 450 мс) — не тормозит.
- **Сортировка** — щелчок по заголовку (▲/▼). Выбор строки **сохраняется** при сортировке и фильтре.
- **Низ — «ДЕРЕВО ПРОИЗВОДСТВА (выбранное изделие)»**: при выборе строки **само** строится дерево:
  - `входит в (все сборки):` — входимость **вверх** до 8 уровней (или пометка «ни в одну не входит»);
  - `◄ заготовка / ◄ отливка: X` — из чего сделано изделие (+ **оснастка** этой отливки);
  - `модельная оснастка (MFG):` — модели оснастки (по связям и по общему префиксу имени);
  - `состав:` — сборка вниз (дети с количеством `xN`), раскрытие — по клику.
  - Разделитель между таблицей и деревом **тянется мышью**.
- **Двойной щелчок по строке** (или `История выбранного`) — история файла отдельным окном.

## Вкладка «Дерево» (верхние сборки со входимыми изделиями)

- Режимы радиокнопками: **`Входимость (ПЛМ)`** (по умолчанию) и **`Папки`**.
- **Входимость (ПЛМ)** — корень `ВСЁ ПРОИЗВОДСТВО` + **все верхние сборки** (те, что сами никуда не входят).
  Раскрытие узла даёт **ту же ветку, что и нижнее окно**: состав вниз, `◄ заготовка/отливка` (+ оснастка),
  `модельная оснастка (MFG)`, `входит в (все сборки)`.
  По умолчанию вид **свёрнутый**; кнопка **`РАЗВЕРНУТЬ ВСЁ`** разворачивает полностью (≈36 500 узлов, 0.5 с).
- **Папки** — шагание по папкам склада (папки → файлы), тоже с фильтром.
- **Фильтр по всей базе** — по всем словам, во всех колонках (путь, обозначение, наименование, материал).
- Кнопки по выделенному узлу: `СОСТАВ (вниз)`, `ГДЕ ИСПОЛЬЗУЕТСЯ (вверх)`, `ИЗМЕНЕНИЯ по изделию`,
  `ПУРГЕ: ПЛАН`, `ПУРГЕ: в бэкап…` (вывод — в поле под деревом).

## Вкладка «Проводник» (папки склада)

Ленивое дерево **папок склада**, как в Проводнике Windows: сверху — корни базы (например `Z:\PTC`),
раскрытие узла показывает подпапки и файлы. Данные берутся **из базы** (диск не обходится) — открытие
мгновенное; у папки в подписи видно `[N папок, M файлов]`. Кнопка **`Обновить`** перечитывает корни.
**Двойной щелчок по файлу** — история изменений этого файла (как во вкладке «Таблица»).

## Карточка изделия (двойной щелчок в дереве)

Окно с паспортом (обозначение, наименование, материал, объём, ревизия, роль, файлов, входит в сборок)
и кнопками: `История файла (окно)` · `Сборки, куда входит` · `Состав (вниз)` · `Заготовка / отливка`
(в обе стороны) · `Файлы изделия`. Окно одно на изделие.

## История файла

Полноценное окно: `Ревизия · Дата · Пользователь · Компьютер · Версия Creo · Что изменено`
(+ старые записи Pro/ENGINEER), фильтр по датам, сортировка по заголовку, выгрузка в CSV,
одно окно на файл. Без окна: `python plm_reader.py --history "путь\модель.prt.1" [--history-csv out.csv]`
(принимает файл, несколько файлов или папку).

## Что обновляется и когда («актуально / нужен скан»)

- **`Актуально?`** — быстрая проверка (обход + `os.stat`, **файлы не читаются**): сравнивает размер и время
  с базой и отвечает `БАЗА АКТУАЛЬНА` либо `НУЖЕН СКАН: новых N · изменённых M · пропало K`. 1.0–1.2 с.
- **`Сканировать`** — инкрементальный скан: неизменённое **не перечитывается** (повтор — секунды);
  изменившееся перечитывается и **сразу** пишется в журнал «что изменилось»
  (объём, материал, имя, обозначение, ревизия, автор, дата, роль). Кнопка `Стоп` прерывает.
- Полное перечитывание (разово, дозаполнить поля и связи): `engine.py scan --roots Z:\PTC --full --limit 0`.

## PURGE (старые версии)

- `ПУРГЕ: ПЛАН` — считает **из базы** (диск не обходится): у каждого изделия остаются `ПУРГЕ: оставить версий`
  новейших, остальные — кандидаты; показывает список и пишет отчёт рядом с инструментом
  (`reports\PURGE_plan_*.txt`; дома — в `D:\AI\log\reports\`). **Файлы не трогаются.**
- `ПУРГЕ: в бэкап…` — с подтверждением **встроенным движком ПЛМ** переносит лишние версии в
  `<папка>\_purge_backup\ГГГГММДД\` (только `move`, удаления нет). Внешний `purge_versions` не нужен.

## Движок и командная строка

- **`engine.py`** — движок ПЛМ (база, скан, дерево, входимость, журнал, ПУРГЕ):
  ```
  python engine.py scan   [--roots П1 П2] [--max-mb 8] [--limit 0=без предела] [--max-depth N] [--full]
  python engine.py check                      # актуально / нужен скан (файлы не читаются)
  python engine.py where  <модель>            # в какие сборки входит
  python engine.py tree   <модель> [--depth 4]# состав вниз
  python engine.py changes [--n 40]           # журнал изменений
  python engine.py count                      # строение склада (папки/файлы/модели)
  python engine.py rename-plan <модель> <нов> # план переименования (Creo не нужен)
  ```
- **`plm_reader.py`** — окно (и режим без окна): `--folder ПАПКА [--csv out.csv]`,
  `--history ПУТЬ… [--history-csv out.csv]`, `--max-mb`, `--no-recurse`.
- Переменная `PLM_DB=<путь>` — своя (другая) база, удобно для проб и переноса.

## Настройки

`settings.json` рядом с программой (заполняется сам): папка, порог размера, обход подпапок,
только последние версии, глубина папок, «ПУРГЕ: оставить версий», набор столбцов, имена параметров.

### Имена параметров и составные поля (шаблоны)

В «Столбцы и параметры…» для полей **Обозначение / Наименование / Материал** задаётся **список правил**
через `;` — берётся **первое непустое**. Правило — это имя параметра ИЛИ **шаблон**:
- `{ИМЯ}` — значение параметра;
- `"текст"` — литерал (**кавычки в колонку НЕ выводятся**);
- `+` — склейка без пробела; обычный пробел в правиле = пробел в выводе;
- пустые параметры **отбрасываются** (нет «хвостов» и двойных пробелов).

Примеры правил:
```
Наименование: {NAME_1} {NAME_2} ; НАИМЕНОВАНИЕ
Материал:     {PTC_MATERIAL_NAME} + " " + {PTC_MATERIAL_DESCRIPTION} ; МАТЕРИАЛ
Обозначение:  {ОБОЗНАЧЕНИЕ} ; OBOZNACHENIE ; DESIGNATION
```
При `NAME_1 = "M5x20"`, `NAME_2 = "ГОСТ 11738-72"` колонка покажет **`M5x20 ГОСТ 11738-72`**;
если `NAME_1` пусто — `ГОСТ 11738-72`. **Модель не меняется** — это правило вывода.

## Ограничения (честно)

- Если в файле детали записан только **внутренний код** базовой модели — имя отливки не восстановить:
  в дереве будет пометка «имя не найдено». Оснастка «по имени» ищется по общему префиксу.
- Входимость показывается для тех изделий, связи которых есть в базе (после скана).
- Инструмент — средство инвентаризации дома; он не продукт PTC и не заменяет Creo.
- Программа **не изменяет, не переименовывает и не перемещает** файлы; `ПУРГЕ` только переносит в бэкап.
- **Обозначение** читается как **параметр ИЛИ отношение** (`ОБОЗНАЧЕНИЕ = rel_model_name`); у самых старых файлов
  нет ни того, ни другого — там обозначение только в **штампе чертежа** (пока не читаем).
- **Поиск параметра «везде»** (все теги, UTF-8/cp1251) изредка даёт **ложное** значение — сверяйте выборочно.
- **Дата** берётся из истории **внутри** файла (парсер читает её не у всех); `Создан`/`Изменён` — даты **файла** (есть всегда).

## Журнал

Работа пишется в общий журнал дома: `D:\AI\log\plm_reader\` — `plm_reader.log` (обходы, истории)
и `engine.log` (скан, проверка, ошибки). Уборка — `log_clean` по `retention.json`.

## Общая база на складе и защита

ПЛМ рассчитан на **одну общую базу на складе** (например на `Z:`), которую смотрят все.

- **Просмотр — всем и параллельно, без замка.** Окно читает базу в режиме «только чтение»
  (`PRAGMA query_only`) — случайно ничего не запишет.
- **Скан — один писатель.** Пока один сканирует, нажавший «Сканировать» получит
  `Занято: идёт скан на <машина> с <время> (пользователь <логин>)`.
- **Замок** — файл `plm.lock` рядом с базой: создаётся атомарно, обновляется сердцебиением (~30 с);
  если владелец упал (метка старше 3 минут) — замок считается протухшим и его можно перехватить;
  снимается автоматически по завершении (даже при ошибке).
- **Публикация без замены файла (V8).** Скан читает активную базу в **локальный черновик**, работает
  с ним, а в конце пишет **новый файл** `plm_reader_ГГГГММДД_ЧЧММСС.db`; читатели берут **свежайший**.
  Существующий файл **не заменяется и не переименовывается** — значит `WinError 5` («файл занят
  смотрящим») невозможен. Старые версии (сверх 3) удаляются, бэкап идёт в `db\backup\`.
- **Склад по сети читать можно** — опасно только писать «в живой» файл базы. Поэтому файл базы никогда
  не переписывается: каждый скан — новый файл.
- **Автообновление окна (V9).** Окно раз в ~15 с проверяет, не появился ли файл базы новее, и перечитывает
  таблицу (фильтр и выделение сохраняются) — так второе окно узнаёт, что базу обновил другой ПК.
  Переключатель «автообновление» — вверху, вкл по умолчанию. Много читателей и один писатель — без конфликтов.

## Где данные и как делиться (важно)

**Код сверху, данные — в подпапке `db\`:**

```
db\                            ← ВСЁ, что накопилось (в гит не идёт, при передаче пропускается)
  plm_reader_ГГГГММДД_ЧЧММСС.db — ОПУБЛИКОВАННЫЕ базы: каждый скан = новый файл; читается СВЕЖАЙШИЙ
  plm_reader.db                — legacy-база (старая схема / первый запуск); запасная
  scan_cache.json              — кэш прочитанных паспортов (повторный скан не перечитывает файлы)
  backup\plm_reader_*.db       — автобэкап предыдущей базы перед каждой публикацией
  plm.lock                     — замок скана (существует только во время скана)
```

- **Делать руками ничего не надо** — активную базу окно выбирает само: свежайший
  `plm_reader_ГГГГММДД_ЧЧММСС.db`, иначе `plm_reader.db`. Замены/переименования файла базы не происходит,
  поэтому «файл занят» не мешает скану.
- **Хранятся 3 последние базы** (старые удаляются), плюс бэкапы в `backup\`.
- **Делиться инструментом** — копировать папку **без `db\`**:
  `SHARE_copy.bat "D:\куда\положить\plm_reader"` (robocopy сам пропускает `db`, `__pycache__`,
  `*.db`, `scan_cache.json`). На принимающей стороне база **соберётся сама**: запустить окно → `Сканировать`.
- **Перенести базу** на другую машину: положить файл(ы) `db\plm_reader*.db` рядом с кодом (или задать `PLM_DB=<путь>`).
- **Совместимость (важно):** читающие окна версий **≤V7** видят только legacy `plm_reader.db` и не видят
  новых `plm_reader_*.db`; скан со старой сборки пишет прямо в общий файл (опасно). **На всех машинах — V8.**
