## 0. ГЛАВНАЯ МЫСЛЬ (одним абзацем)

ПЛМ отвечает на четыре вопроса:
**① ЧТО это за изделие?** (паспорт) · **② ИЗ ЧЕГО оно состоит / КУДА входит?** (связи) ·
**③ ЧТО с ним происходило?** (история и изменения) · **④ КАК его изготовить?** (технология).

Файл Creo — **единственный источник правды** (`Z:`). База — **производная**, её можно
**пересобрать с нуля** (§README «ТРИ ЖЕЛЕЗНЫХ ПРАВИЛА» п.3). Сканер читает файл **один раз** —
в этом вся ценность: **один проход даёт все четыре ответа**.

**ЗАКОН:** «в файлах мусора НЕТ» — не разобрано ≠ мусор (отложенная работа, `unknown_fields`).
**НО:** хранить всё ≠ писать миллионы служебных строк (см. §README «ОЦЕНКА РАЗМЕРА»).

## 2. СВЯЗИ И ДЕРЕВО — «из чего состоит / куда входит»

**ОДНА таблица `links`** несёт связь: `parent` · `child` · `qty` · `source` · `origin` · `kind`
(§5.1: было 6 таблиц-«блоков» → осталась одна).

| Вид связи | `kind` | Признак в файле | Значение для ПЛМ |
|---|---|---|---|
| **состав сборки** (BOM вниз) | `structure` | компоненты `.asm` (`asm_comp`) | спецификация, сборка |
| **входимость** (вверх) | `structure` (built) | достраивается ПО базе | где применяется деталь |
| **наследование** | `inherit` | `MERGE_BASE_PART` | заготовка / отливка / мастер |
| **производная** | `proizv` | `ref_part_tab` (из СВОЕЙ папки) | обработка ← деталь |
| **копия** | `копия` | `from_mdl_name` → `to_mdl_name` | save-as, зеркало |
| **свойство** | `prop` | наследуется ЛЮБОЕ свойство (§М.1г) | материал/слой/геометрия |
| **исполнения** | `family` | таблица семейства (`.prt`) | типоразмеры (DIN912-M10…) |
| **упоминание** | `mentions` | имя в параметре/комментарии | «широкий» след, НЕ состав |
| **оснастка** | `structure` | `.asm`-обработка: заготовка `_Z` · инструмент `T00*` | технология |
| **чертёж ↔ модель** | `drawing` | имя `.PRT` в `.drw` | комплект: prt+asm+drw |

**🔴 ДОГМА (§85):** связи строятся **ТОЛЬКО ОДИН РАЗ** — в `plm_graph.plm_edges()`, из **ОДНОЙ**
базы. Второй `SELECT FROM links` где-либо = **баг**. Разный **вывод** — норма, разные **связи** — нет.

**🔴 СТРОИТЬ ВСЁ — ОБРУБАТЬ ВЫВОД (§4а):** любая найденная связь **пишется в базу** без исключений
(детали, формы, оснастка, библиотека, шаблоны, свойства). Отсев — **только на выводе и только
настройкой**. Родителей может быть сколько угодно — **каждая запись = отдельная связь**.

**🔴 `real` / `built`:** потомок знает родителя, а **родитель — нет**; сборка знает компонент, а
**компонент — нет**. Обратное **достраивается** отдельным проходом (`plm_build_links.py`),
идемпотентно, реальную связь не дублирует. По колонке `origin` видно, **где ошибка**:
неверно в `real` → правим **сканер**; в `built` → правим **достроитель**.

**5-слойная модель производства (§5, источник — подсказки Gemini):**

| Уровень | PLM-класс | Признак в файле |
|---|---|---|
| 1 | **КД Мастер** | `FeatDefs` (чистая геометрия) |
| 2 | **Деталь-Заготовка (_Z)** | `MERGE_BASE_PART` (наследование) |
| 3 | **Деталь-Отливка (_O)** | `PTC_SHRINKAGE_FACTOR` (усадка) |
| 4 | **Мастер Оснастки (MSTR)** | `Parting_Surface` / `Core_Print` |
| 5 | **CAM-Процесс (ASM_MFG)** | `FullMData` (скорости/подачи/траектория) |

## 7. РАЗМЕРЫ И ХРАНЕНИЕ — «не раздувать»

**Замер 03.11.2026** (20 файлов → черновик): 8.8 МБ · 28 263 строки · 1 413 строк/файл.
Прогноз склада (64 818 файлов): **≈ 91.6 млн строк ≈ 28–31 ГБ**.

| Источник раздувания | Строк/файл | Доля | Лечение |
|---|---|---|---|
| `unknown_fields` | **1 303** | **92%** | агрегат на файл ЛИБО фильтр `count > N` |
| `matrices` | 98.6 | 7% | хранить только заполненные (`vals ≠ []`) |
| прочие 10 таблиц | 11 | 1% | — |

**Цель:** ≤ **0.15 МБ черновика на файл** (сейчас 0.44 МБ) → прогноз склада ≤ 10 ГБ.

**Слои хранения (§5.2 STRATEGY):**

| Слой | Где | Примечание |
|---|---|---|
| единая база | `db\plm_reader_ГГГГММДД_ЧЧММСС.db` | одна, публикуется новым файлом |
| превью | `db\media\` | файлы вне базы |
| индекс превью | `db\media_cache.json` | не сами картинки |
| бэкапы | `db\backup\` | последние 3 (`BACKUP_KEEP`) |
| архивные срезы | `arch_*` | история склада (RAR5) + `changes(kind='архив')` |

**Механизм публикации:** скан → **черновик** → **публикация** (`_publish`: бэкап + версионный файл +
атомарная подмена). **Прямая запись в боевую ЗАПРЕЩЕНА.** Боевая база не меняется до успеха.
