# db_profile V1 — профиль баз данных дома (класс Р, только чтение)

## Зачем
Волна 1 плана: общая `agent.sqlite` (230 МБ) смешала **мозг** агента (`chat`, `history`,
`trail_*` — сотни строк) и **свод** (`models`/`files`/`bom`/`fts` — все 230 МБ). По канону свод
должен жить в локальной `db\` инструмента, общая остаётся мозгом. Этот инструмент **показывает**,
кто сколько весит, чтобы миграция (спека Волны 1) шла по цифрам, а не на глаз.

## Что делает
1. Для каждой базы (по умолчанию `data/agent.sqlite` + `data/harvest.db` из настроек):
   размер файла, число таблиц, строки в каждой, оценка байт (`dbstat`, иначе `page_count`);
2. Размечает таблицы по зонам: **мозг** (пишет агент) / **свод** (данные инструментов) / **fts**;
3. Если свод крупнее мозга — печатает рекомендацию: свод кандидат в локальную `db\`.
4. **Только чтение** (`mode=ro`): на живой базе безопасен, ничего не пишет и не меняет.

## ОКНО / КОНСОЛЬ
```
python db_profile.py                  # профиль баз из настроек
python db_profile.py <путь> [<путь>]  # профиль конкретных баз
python db_profile.py --json           # машиночитаемо
```
Код возврата: 0 — прочитано · 2 — базы нет (нечего профилировать).

## Границы
- Ничего не мигрирует и не чистит — это **измерение**, а не действие.
- `dbstat` может быть недоступен в сборке sqlite — тогда печатает строки без оценки байт (не падает).
- Пути к базам — из настроек (относительно `tools\agent`), абс. путей в коде нет (канон №2).
