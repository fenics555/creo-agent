# harvest — СБОРЩИК ДОМА (индекс моделей, пар «чертёж↔PDF», вхождений)

**Что это.** Ночной (и ручной) обход путей дома: находит файлы, пишет их в индекс
`data\harvest.db`, обновляет **пары «модель/чертёж → PDF»** и собирает вхождения (instances).
По этому индексу потом работают `pdf_refresh` (старое), `orphan_scan`, `navigator` и поиск в агенте.

**Класс Р** (руки без Creo и без модели). Creo не нужен. Но пути домовые: `D:\AI\tools\agent\data\harvest.db`,
`D:\AI\log\harvest\harvest.log`, корни — из файла корней (`--roots`) или `DEFAULT_ROOTS`.

## Как звать
```
python harvest.py                       # полный прогон по корням дома
python harvest.py --roots <файл>        # свой список корней (по строке на путь, комментарий — «#»)
python harvest.py --allow-z             # разрешить корни на Z: (по умолчанию Z пропускается словом)
python harvest.py --text                # дополнительно индексировать тексты (txt/md) для поиска
python harvest.py --bench               # в конце напечатать скорость (файлов/с)
```
Окно: `python harvest_gui.py` (агентский интерфейс: прогон, прогресс, остановка по PID замка).
Остановка: `python harvest.py` из окна агента или `harvest.stop()` — по PID из `data\harvest.lock`.

## Живые находки 23.09.2026 (обе исправлены здесь)
1. **Индекс не пополнялся Creo-моделями — вообще.** В базе у файла `деталь.prt.1` расширение записано как
   `.1`, а фильтр прогона ждал `prt` → **все** Creo-файлы отсекались (`added=0`).
   Исправлено функцией `_logical_ext()` (по имени и версии берётся настоящее расширение).
   Проверено живьём: тестовая папка → **было `added=0`, стало `added=3`**.
   Это значит, что до правки ночной прогон не обновлял модели — теперь обновляет.
2. **Файл корней читался жёстко в utf-8** → если он сохранён в cp1251 (частый случай у PowerShell),
   прогон падал `FATAL: 'utf-8' codec can't decode byte 0xcf`. Теперь `utf-8-sig`, при ошибке кодировки — честный откат на cp1251.

## Что важно знать про безопасность прогона
- **удаление ограничено сканируемой папкой**: `old_here = [p for p in old if p.startswith(root)]`,
  затем `deleted = old_here - seen_here`. Значит прогон по одной папке **не тронет** остальной индекс —
  можно спокойно прогонять по частям;
- `Z:` по умолчанию **не сканируется** (нужен `--allow-z`) — защита от случайного обхода всей шары;
- замок `data\harvest.lock` не даёт двум прогонам работать одновременно; «мёртвый» замок снимается сам
  (проверка PID);
- если корень «спит» (недоступен) — прогон помечает его `asleep` и идёт дальше, ничего не удаляя.
