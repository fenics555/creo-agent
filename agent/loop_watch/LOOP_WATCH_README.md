# loop_watch — СТОРОЖ ПЕТЕЛЬ НОГИ (V1, 23.11.2026)

**Что это.** Внешняя программа-наблюдатель: читает историю сессии Cline **сбоку** и сигналит,
когда нога (ИИ-агент) зациклилась. Модель **в моменте свою петлю не видит** — каждый её ход «первый»;
сторож видит последовательность и ловит повтор.

**Файл:** `D:\AI\tools\agent\loop_watch.py` (10 645 б; только стандартная библиотека Python, зависимостей нет).
**Класс Р** — Creo, модель и диск `Z:` не нужны. Читает **локальные данные Cline**:
`%USERPROFILE%\.cline\data\sessions\` и `%USERPROFILE%\.cline\data\logs\code.log`.

## Как звать

```
python D:\AI\tools\agent\loop_watch.py              # режим-цикл, опрос каждые 4 с (нужен запущенный Cline)
python D:\AI\tools\agent\loop_watch.py --once       # разовая проверка новейшей сессии
python D:\AI\tools\agent\loop_watch.py --session <id>   # конкретная сессия
```

Готовые входы (двойной щелчок):
- `loop_watch.bat` — **ручной запуск**, видимое окно, работает в цикле (закрыть окно = остановить);
- `loop_watch_once.bat` — **разовая проверка** (окно не закрывается, печатает сигнал);
- `loop_watch_hide.bat` — **фоновый запуск** (свёрнутым окном): для «пусть работает всегда».

## Что ловит (пороги — константы в начале скрипта)

| сигнал `kind=` | условие | порог |
|---|---|---|
| `tool-loop` | один и тот же `инструмент+аргументы` упал ≥2 раз | `THRESHOLD=2` |
| `cycle-loop` | качели `A-B-A-B` в окне вызовов | `CYCLE_PAIRS=2` |
| `error-loop` | ≥3 падения с одинаковой **подписью** ошибки | `ERR_SIG_THRESHOLD=3` |
| `fail-loop` | ≥3 **любых** провала инструментов в окне | `FAIL_THRESHOLD=3` |
| `text-loop` | одинаковый текст (≥20 симв.) повторён 3 раза | `TXT_REPEAT=3` / `TXT_WINDOW=6` |
| `aborted` | последний ход в `code.log` = `finishReason:"aborted"` | — |
| `--stall` (выкл. по умолчанию) | сессия не растёт `STALL_SEC`, бэкенд жив | `STALL_SEC=110` |
| `--spike` (выкл. по умолчанию) | файл сессии вырос за тик | `SPIKE_BYTES=65536` |

### INBOX-инъекция КРАХА (25.11.2026) — самолечение

При любом сигнале сторож пишет в **`D:\AI\INBOX.md`** (аргумент `--inbox`):
```
КРАХ — признак <kind> (повторов N). Крах-скилл: <SKILL_crash_...>
```
**Только ФАКТ + имя крах-скилла, без рекомендаций** — правило `.clinerules` (КРАСНЫЕ ЛИНИИ) обязывает
модель при §4.7-триггере прочитать INBOX → вывести `REVIVE:` (4 пункта) → **сверить `SKILL_crash_index.md`
и зафиксировать сбой по `SKILL_crash_constitution.md`** (§5.2) → очистить INBOX.
**Проверено:** инъекция «КРАХ» посередине диалога → модель открывает REVIVE; с признаком — даёт разбор.

Окно наблюдения — последние `WINDOW=12` вызовов (старые ошибки не дают вечный ALERT).
Крупные чтения файлов со словом «error» ложных срабатываний **не** дают (`ERR_MAX_LEN=4000`).
Антиспам: `COOLDOWN_SEC=20` на повтор того же события.

## Автоудаление записей (retention) — 23.11.2026

**Кнопки нет — чистка автоматическая.** Срок берётся из дома: `D:\AI\log\retention.json`, ключ **`urn`**
(сигналы лежат в urn-папке `log\urn\cline\`); сейчас это **14 дней**. При сбое чтения — те же 14.

Когда срабатывает:
1. **при каждом запуске** (ручной `.bat`, разовый `--once`, фоновый `--hide`);
2. **после каждой новой записи** сигнала.

Что делает:
- удаляет строки старше срока (`cutoff = сегодня − urn`);
- **мигрирует старые строки без даты**: им проставляется дата файла (иначе они бы не состарились никогда);
- страховка по размеру: даже внутри срока файл не превышает `MAX_ALERT_BYTES = 1 000 000` байт
  (лишнее срезается с начала);
- перебить срок вручную (для тестов): `--keep-days N`.

Проверено 23.11.2026 на фикстурах:
- старая датированная строка (`2026-10-30`) → удалена (`pruned 1`), свежая осталась;
- строка без даты (`22:55:57 LOOP …`) → переписана как `2026-11-23 22:55:57 LOOP …` и сохранена.

## Как читать сигнал

1. `kind=aborted` — ход оборван (таймаут/отмена): смотреть `code.log` и размер окна.
2. `kind=tool-loop` / `cycle-loop` — повтор одного вызова: правило дома «2 провала подряд → REVIVE».
3. `kind=error-loop` — одна и та же ошибка с разными аргументами (часто битый якорь/путь).
4. `kind=fail-loop` — «мятущийся» провал: разные ошибки подряд (переписывание своего же скрипта).
5. `kind=text-loop` — модель повторяет один и тот же ответ текстом.
