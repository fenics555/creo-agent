## ДВИЖОК (для ИИ и скриптов)

**ШТАТНЫЙ ЗАПУСК CREO (без CREO-START.bat).** Домашний бат делает ровно две вещи: `cd /d START-STD` и
`start parametric.exe` — **без ключей**. Значит штатный запуск = задать процессу `parametric.exe`
**рабочую папку с боевым `config.pro`**: Creo читает `config.pro` из рабочей папки, а оттуда приходят
форматки (`pro_format_dir`), `MY_ESKD.dtl` и `table.pnt`. Путь установки берётся из реестра Windows:

```
    CommonFilesLocation REG_SZ  D:\PTC\CREO12\Creo 12.4.2.0\Common Files
```

## КОНФИГ И ОФОРМЛЕНИЕ (почему PDF «правильный»)
PDF берёт оформление из живой сессии, а сессия — из `config.pro`:
| Опция | Значение дома |
|---|---|
| `pro_format_dir` | `Z:\PTC\CREO-START\НАСТРОЙКИ\ФОРМАТЫ\` (163 форматки `a0…a4.frm`) |
| `drawing_setup_file` | `…\НАСТРОЙКИ\configs/MY_ESKD.dtl` — оформление чертежа (ЕСКД) |
| `format_setup_file` | `…\configs/MY_ESKD.dtl` в файле; **в живой сессии `dwgform.dtl`** |
| `pen_table_file` | `…\НАСТРОЙКА_ПРИНТЕРА/table.pnt` — перья/толщины линий |
| `pro_plot_config_dir` | `…\НАСТРОЙКА_ПРИНТЕРА\` |
| `pdf_use_pentable`, `use_8_plotter_pens` | `yes`, `yes` |
**Разница `format_setup_file` / `drawing_setup_file`:** `format_setup_file` задаёт настройки, которые
**зашиваются в форматку** (внутренний `dwgform.dtl`) — он применяется, когда форматка подгружается/создаётся;
`drawing_setup_file` применяется **к самому чертежу** (тексты, стрелки, допуски) и обновляется при работе с чертежом.
Практический вывод: если чертёж уже с домашней форматокой, PDF верен; если форматки нет — её нужно подтянуть
(`pro_format_dir` + `format_setup_file`), иначе PDF будет «пустым» по оформлению.

**Как программа узнаёт каталог Creo:** `config-find` берёт `cwd` живой сессии (там Creo и стартовал —
для дома это `Z:\PTC\CREO-START\START-STD`), профиль пользователя и loadpoint Creo, вычисленный
из `java.library.path` (`…\Common Files\x86e_win64\lib` → два уровня вверх). Первый найденный `config.pro`
и есть боевой.

## СБОРОЧНЫЕ ЧЕРТЕЖИ И УБОРКА (проверено 23.09.2026)
- **Сборочный чертёж** (`X.drw` при наличии `X.asm`) Creo не отдаёт «в голове»: `XToolkitNotFound`.
  Движок теперь **сначала поднимает сборку `X.asm`**, затем чертёж — и это работает:
  `plshaiba-4` и `plshaiba-5` (оба были «ОШИБКА») дали `PDF OK 35879 б` и `PDF OK 28592 б`, **0 ошибок**.
- **После экспорта чертёж убирается из сессии** (`Model.Erase()`), если он не был открыт инженером раньше —
  окна в Creo накапливаются только при желании. Если чертёж был в сессии ДО прогона — не трогаем.
- **Просмотрщик PDF** управляется явно: опция `PDFOPT_LAUNCH_VIEWER` = по галочке «открывать PDF»;
  без галочки ничего не открывается (и открывать PDF своими руками движок не будет).
## PDF НЕ РЯДОМ С МОДЕЛЬЮ (проверено 23.09.2026)
Отдельный режим: `python creo_pdf_orphans.py <папка> [--limit N]` (в окне — кнопка «PDF без модели рядом»).
Обходит папку **и все подпапки**, берёт каждый `.pdf` и смотрит, есть ли **рядом** файл модели
(`<имя>.drw/.prt/.asm/.frm[.N]`). Если нет — ищет имя в **домашнем индексе агента**
(`agent.sqlite: models` 44 тыс.; `harvest.db: models_raw` 93 тыс.) и говорит, ГДЕ модель лежит.

## PDF НЕ В СВОЕЙ ПАПКЕ И КОПИИ (проверено 23.09.2026)
`python creo_pdf_misplaced.py <папка> [--limit N] [--doc]` — отчёт; `[--apply]` — уборка.
Группирует по имени файла и показывает **все** копии PDF: где чертёж, какая копия **рядом**,
какие **в других папках**, их размеры и даты, и помечает `копия СВЕЖЕЕ той, что рядом` (тогда правильной
может оказаться «не та» копия — сначала перевыпустить рядом, потом убирать).
```

        НЕ РЯДОМ (    45149 б, 16.01.2023 16:02)  Z:\PTC\Work\…\401-CK50-FMB27 Оправка…\401-bt40-fmb22-002.pdf
НЕТ РЯДОМ  freza   [чертёж найден по индексу дома; копий: 1]
        чертёж: Z:\PTC\Work\У-1.00.001 НАПРАВЛЯЮЩАЯ СП-№2
        НЕ РЯДОМ (   583563 б, 19.02.2016 11:52)  Z:\PTC\Work\…\Дисковая для рычагов\freza.pdf
ДУБЛЬ     ст-чпу-12-01  … НЕ РЯДОМ (20408 б, 30.10.2020 16:00) … <-- ВНИМАНИЕ: копия СВЕЖЕЕ той, что рядом
ИТОГО: групп с копиями не там 4 (без копии рядом 1, дублей 3), PDF-от-модели 2, документации 22, чертежей без PDF 67
```
**Правила перемещения в корзину инструмента (`_trash\<дата>`; безвозвратного удаления нет):**
- «Искать дубли ПДФ и не рядом» + галочка: перемещаются только **лишние** копии — когда правильная копия
  **рядом с чертежом уже есть**; единственная копия без пары рядом и документация НЕ трогаются;
- «Искать ПДФ без модели» + галочка: перемещаются только **настоящие сироты** (нет модели ни рядом,
  ни в индексе дома) — PDF, чья модель есть в другой папке, не трогается;
- всё перемещённое (и дубли, и сироты) лежит в `creo_pdf\_trash\<дата>` или `_trash\<дата>_nomodel` — вернуть руками;
- проверено на тестовом дереве: дубли и сироты уехали в корзину, правильные пары и чертежи остались на месте.

## ГРАБЛИ
1. `export`/`pdf`/`config-*` требуют **запущенного Creo**; `scan`/`config-find` — нет (`config-find` — да, требует).
2. Creo, запущенный из `D:\PTC\CREO-LOCAL-SETUP\CREO-LOCAL-START` (его `config.pro` 12 761 б **без** домашних путей),
   даст PDF без форматок и перьев — лечится `config-load` или стартом из `START-STD`.
3. Creo дописывает суффикс версии к экспорту (`name.pdf` → `name.pdf.1`), если файл занят.
4. Пути с пробелами/кириллицей — только в кавычках; движок терпит лишние кавычки.
5. Долгий прогон на большой папке: ставь `лимит` и дели по корешкам; окно можно остановить кнопкой СТОП.
