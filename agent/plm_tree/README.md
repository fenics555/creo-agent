# plm_tree — V1

ПЛМ «в лоб»: читает модели Creo **напрямую из файлов** (Creo не нужен) и ведёт свою базу:
паспорт изделий, **входимость** (в какие сборки входит и сколько раз), **дерево производства**
и **журнал изменений** (кто/когда/что).

База лежит **рядом с инструментом** — `plm_tree.db` (легко перенести на другую машину).

## Запуск (CLI)
```
plm_tree.bat scan                 обойти корни, обновить паспорт и связи, записать изменения
plm_tree.bat where МОДЕЛЬ         в каких сборках участвует и сколько раз
plm_tree.bat changes              последние изменения из журнала
```
Параметры `scan`: `--roots "путь1" "путь2"` (по умолчанию два производственных корня),
`--limit СЕК` (лимит времени прогона), `--max-mb N` (пропускать файлы больше N МБ).

## Что пишет в базу
- `snapshots` — паспорт каждой модели (путь, размер, объём, материал, наименование, обозначение,
  ревизия, автор, дата, роль) — по нему и ловится изменение;
- `changes` — события: `new` (первая запись) и `modify` (что поменялось: объём/материал/имя/ревизия/роль);
- `links` — `parent · child · qty` (входимость: сколько раз компонент входит в сборку).

## Как понимает ИЗМЕНЕНИЯ (устойчиво к purge)
Не по номеру версии (после чистки снова `.1`), а **по содержимому**: текущий паспорт сравнивается
с прошлым снимком в базе. Отличие → событие «было→стало» сразу в журнал.

## Состав папки
```
plm_tree.py    — движок + CLI (одна библиотека)
plm_tree.bat   — запуск без окна (аргументы)
plm_tree.db    — СВОЯ база (создаётся при первом scan)
README.md      — этот файл
```

## Лог
`D:\AI\log\plm_tree\plm_tree.log` — каждый прогон строкой (что сделано, сколько, за сколько секунд).

## Окно
Запуск двойным щелчком: `plm_tree_gui.bat`.
- **Слой 1 (настройки):** Корень 1 / Корень 2, «Лимит, с», путь к своей базе, кнопка **README** (выводит этот файл в окно).
- **Слой 2 (рабочие):** `СКАНИРОВАТЬ` · `ДЕРЕВО` · `ГДЕ ИСПОЛЬЗУЕТСЯ` · `ИЗМЕНЕНИЯ`.
- Внизу — **время работы** («сканирование: за X с»). В поле «Модель» задаётся изделие для «ДЕРЕВО»/«ГДЕ ИСПОЛЬЗУЕТСЯ».
