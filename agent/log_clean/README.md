# log_clean — УБОРКА ЛОГОВ дома (класс Р, автономная программа)

**Что решает.** В `D:\AI\log\` у каждого инструмента свой каталог, и они растут годами. Программа
смотрит каталоги, сверяет возраст файлов со **сроком хранения** и убирает старое. Сроки лежат в
`D:\AI\log\retention.json` — **тот же файл читает ночной цикл агента**, поэтому цифры одни на всех.

⚠️ **По умолчанию ничего не удаляется**: старое уезжает в корзину `D:\AI\log\_trash_clean\<дата>\`
и живёт там 7 дней (тоже настраивается). Безвозвратное удаление — отдельный переключатель.
Класс Р: **Creo не нужен, агент не нужен.**

## Два способа запуска

**Окно (рекомендуется):** `log_clean_gui.bat`
- поля настроек: **Корень логов**, **срок по умолчанию**, **что делать со старым** (корзина/удалить),
  **сколько держать корзину**;
- таблица: каталог · файлов · срок дн. · старше · МБ · занятых · самый старый · последний;
- **двойной щелчок по строке** — задать срок ИМЕННО этому каталогу (пишется в `retention.json`);
- кнопки: **ОБНОВИТЬ ПЛАН**, **УБРАТЬ СТАРОЕ** (спрашивает подтверждение), открыть папку логов,
  открыть корзину;
- внизу — что сделано, куда ушло, что пропущено и почему.

**Консоль:** `log_clean.bat` (план) · `log_clean.bat --apply` (в корзину) · `log_clean.bat --apply --delete`.

## Что считает и как щадит
- каталоги `D:\AI\log\<имя>\` — по одному сроку на каталог (в `retention.json`),
  для незнакомых — срок по умолчанию;
- **вложенные папки тоже считаются** (`urn\<исполнитель>\<тема>\`, `reports\<тема>\`) и файлы прямо
  в корне `log` (срок по умолчанию или ключ `root` в `retention.json`). Живая находка 24.09.2026:
  раньше смотрели только файлы в подпапках первого уровня, поэтому обещанные сроки для урны (14 дней)
  и отчётов (28 дней) **не работали** — в `urn` накопилось 1548 файлов, из них 255 старше срока (8,8 МБ),
  а 15 МБ в корне `log` не видел никто;
- при уборке вложенная структура сохраняется и в корзине (`_trash_clean\<дата>\urn\cline\<тема>\…`):
  иначе одноимённые `out.txt` из разных тем перетирали бы друг друга и вернуть файл было бы нельзя;
- **занятый файл** (открыт другой программой) пропускается, причина пишется в отчёт
  (проверка: переименование файла в себя — если не вышло, файл занят);
- свои каталоги (`_trash_clean`, `log_clean`) и `retention.json` программа не трогает никогда;
- отчёты прогонов: `D:\AI\log\log_clean\run_<дата>_<время>.json` — видно, что убрано и что пропущено.

## Куда пишет и откуда читает (сверено с живыми вызовами 03.10.2026)
| Роль | Путь | Режим |
|---|---|---|
| ЧТЕНИЕ: каталоги логов | `D:\AI\log\<папка>\…` (включая вложенные) + файлы в корне `log` | чтение |
| ЧТЕНИЕ: сроки | `D:\AI\log\retention.json` | чтение |
| ЗАПИСЬ: корзина (по умолчанию) | `D:\AI\log\_trash_clean\<дата_время>\<каталог>\<путь файла>` | перенос |
| ЗАПИСЬ: удаление навсегда | только с `--apply --delete` | удаление |
| ЗАПИСЬ: сроки | `D:\AI\log\retention.json` | запись (двойной щелчок по строке) |
| ЗАПИСЬ: отчёт прогона | `D:\AI\log\log_clean\run_<дата>_<время>.json` | запись |
| ЗАПИСЬ: настройки окна | `D:\AI\tools\agent\data\log_clean_settings.json` | запись |

**Никакого Creo программа не читает** (проверено поиском по коду: только упоминание в комментарии и
`reports\creoson_crashes\` как обычная папка логов). Поэтому автопоиск установки Creo ей не нужен —
нет ни путей Creo, ни `config.pro`. Класс Р: Creo не нужен.

## Настройки — одно место
| Что | Где | Кто ещё читает |
|---|---|---|
| сроки по каталогам | `D:\AI\log\retention.json` | ночной цикл агента — цифры одни на всех |
| настройки окна (корень, срок, режим, срок корзины) | `agent\data\log_clean_settings.json` | только окно |

Значения по умолчанию в коде — только умолчания; при отсутствии файла программа работает.

## Консоль
```
log_clean.bat                  # план (ничего не трогает)
log_clean.bat --apply          # убрать старое В КОРЗИНУ
log_clean.bat --apply --delete # удалить навсегда
log_clean.bat --root <папка>   # другой корень (для пробы)
log_clean.bat --days N         # срок по умолчанию (минимум 1)
log_clean.bat --trash-days N   # сколько дней держать корзину
```
Коды возврата: **0** успех · **2** нет такой папки · **3** неверный `--days` · **4** ошибка выполнения.

## Что исправлено в аудите 03.10.2026
1. **Занятый файл не опознавался НИКОГДА** (главное). Проверка состояла из двух приёмов, и второй
   ломал первый: на Windows `open(path,'a')` на занятый файл **не падает никогда**, поэтому после
   честного падения `os.rename(path, path)` код шёл в запасной приём и возвращал «свободен».
   Живая проба (файл держит отдельный процесс): было `False` → стало `True`.
   **Значило это**: обещание «занятое не трогаем» не работало — логи открытого агента могли уехать в корзину.
2. **Бат глотал код возврата.** Движок честно отдавал 2 и 3, а `log_clean.bat` всегда возвращал 0
   (`python engine.py %*` без `exit /b`). Планировщик не мог отличить «убрать нечего» от «папки нет».
3. **Кракозябры в консоли** — не было `chcp 65001` и `-X utf8`. Исправлено.

## Границы
- программа работает по **возрасту файла**, а не по смыслу: если что-то нужное лежит давно — либо
  поднимите срок в окне, либо перенесите файл в место, которое уборка не смотрит;
- корень `Z:\...` можно указать в окне, но обычно уборка нужна только для локальных логов;
- «Система» ничего не чистит за пределами указанного корня.
