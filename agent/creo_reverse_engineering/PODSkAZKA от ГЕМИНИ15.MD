🛠️ ЧАСТЬ 1. Точная карта настроек в PLM Reader V99 (Где что лежит)

В вашей архитектуре все конфигурационные параметры, исключения и правила разбора бинарников сведены в один единственный источник истины — файл settings\settings.json (управляется модулем plm_settings.py). Внутри кода зашита константа DEFAULT_SETTINGS.
На основе анализа интерфейса и карты файлов репозитория, запрашиваемые вами настройки распределены по следующим строго определенным узлам:

1.1. Пути папок сканирования и исключений (+ папка / -)

Эти параметры находятся в окне plm_paths_window.py (модальное окно «Пути, исключения и база данных»), которое открывается по кнопке из левой панели plm_toolwin.py:
• Папки сканирования (Корни): В файле настроек это массив строк под ключом "roots". В окне кнопка + папка добавляет запись в список, а кнопка - справа от строки — удаляет её из массива roots. При сканировании (plm_scan.py) движок использует метод engine.as_roots, превращая этот список в итераторы для обхода диска.
• Папки исключений (Blacklist): В файле настроек это массив строк под ключом "exclude_folders". В окне они выведены в раздел «Папки исключений — НЕ читать вовсе». Управление (+ / -) идентично. Движок сканирования (plm_scan.py) на самом раннем этапе отсекает эти пути, а начиная с версии V78, инкрементальный скан принудительно вычищает (DELETE) из таблиц snapshots, links и derived все старые записи, если папка была добавлена в исключения.

1.2. Путь к файлу конфигурации Creo (config.pro) для чтения шаблонов

В коде версии V99 путь к конфигурационной среде Creo Parametric завязан на секцию ШАБЛОНЫ (в файле настроек это ключи "template_folders" и "service_models").
• Строка пути в окне указывает на вашу стартовую директорию (например, Z:\PTC\CREO-START\НАСТРОЙКИ\ШАБЛОНЫ).
• Как это читается «в лоб»: При запуске сканирования (plm_scan.py) утилита engine.service_stems() обращается к этой папке, считывает конфигурационный файл config.pro и текстовые файлы параметров форматок чертежей.
• Парсер вытаскивает из config.pro системные переменные:
	• template_solidpart и template_designasm — чтобы автоматически идентифицировать служебные мастер-модели (например, MM_PART, SBORKA_MFG) и отсекать их из графа, предотвращая ложное ветвление (когда шаблон «входит в 6000 сборок» и мусорит в КД-составе).
	• pro_unit_length / pro_unit_mass — для проверки локали, чтобы расчетная масса отливок рычагов (11.99 кг) и объем в мм³ выводились в метрической системе, а не в американских фунтах/дюймах.

На основе анализа модулей вашего репозитория (plm_parse.py, plm_history.py, engine.py) сформулирована окончательная математическая модель вашего PLM-дерева. 🧱 Поведение ребер и логика слоев в коде V99:

1. Слой 1. Входимость BOM (Синие стрелки «Сверху-Вниз»): Вытаскивается методом _parse_bom_structure из секции NeuAsmSld. Метизы и крепеж (ваш файл SCREWS_VZ.PRT) принудительно дедуплицируются и схлопываются в одну строку графа с весом ребра Quantity = X шт.
2. Слой 2. Наследование и Литье (Красные стрелки «Снизу-Вверх»): Полностью инвертировано. КД-вершина ничего не знает о потомках. Деталь-отливка (_otlivka.prt) сама хранит токен MERGE_BASE_PART (метод _parse_inheritance_genealogy) и double-константу PTC_SHRINKAGE_FACTOR = 1.012, указывая на своего родителя.
3. Слой 3. Трекер копирования (Уникальное решение V58-V62): Модуль engine.copy_from_of(raw) сканирует бинарное тело файлов-потомков, находит маркеры from_mdl_name → to_mdl_name и фиксирует в базе КД-связь типа «модель скопирована от: ИСХОДНАЯ_МОДЕЛЬ.PRT». Это позволяет во вкладке «История файла» выводить честную хронологию мутаций до момента save-as переименования.
4. Слой 4. Технологический Мануфактуринг ЧПУ: Модуль plm_parse.py и экстрактор FullMData забирают данные из тяжелых CAM-сборок (ASSEMBLY/ASSEM_MFG). При этом, если файл скомпилирован на Unix-станции Sun (Big-Endian), переключатель эндианизма _detect_architecture_endian на лету разворачивает байты double-чисел, гарантируя точный вывод скоростей шпинделей (90 000 RPM) и подач (CUT_FEED) во вкладке «Свойства детали».

3.1. Правка для автоматического парсинга config.pro (Внедрить в plm_settings.py)

Этот метод считывает текстовый файл конфигурации Creo, вытаскивает пути к форматкам спецификаций и автоматически добавляет их в массив служебных исключений, чтобы они не засоряли базу.
python
def auto_parse_creo_config_pro(config_path: str) -> list:
    """
    ПРАВКА №1: Автоматический парсинг config.pro 'в лоб'.
    Вытаскивает пути к шаблонам (template_solidpart) и директории форматок (pro_format_dir).
    """
    discovered_service_dirs = []
    if not os.path.exists(config_path):
        return discovered_service_dirs
        
    try:
        with open(config_path, 'r', encoding='cp1251', errors='ignore') as f:
            for line in f:
                line = line.strip()
                if line.startswith('#') or not line: 
                    continue
                # Разбиваем строку config.pro на параметр и значение
                parts = line.split(None, 1)
                if len(parts) == 2:
                    key, val = parts[0].lower(), parts[1].strip()
                    # Ищем переменные путей к форматкам и библиотекам крепежа
                    if key in ['pro_format_dir', 'search_path', 'pro_texture_dir']:
                        clean_path = val.replace('"', '')
                        if os.path.exists(clean_path):
                            discovered_service_dirs.append(clean_path)
    except Exception as e:
        print(f"[-] Ошибка чтения config.pro: {e}")
        
    return discovered_service_dirs
Используйте код с осторожностью.

3.2. Правка для Кросс-Платформенного Чтения FeatDefs (Внедрить в plm_parse.py)

Заменяет старую логику разбора, гарантируя strict 16-bit прыжок по указателям с учетом переключателя порядка байт для SunOS BE и Windows LE.
python
def parse_feat_defs_strict_v99(fd_bytes: bytes, endian_mask: str) -> list:
    """
    ПРАВКА №2: Строгий побайтовый разбор дерева фичеров и бэкапов размеров.
    Использует маску порядка байт (endian_mask: '<' или '>'), полученную при анализе заголовка.
    """
    mutations_log = []
    cursor = 0
    limit = len(fd_bytes)
    
    while cursor < limit - 16:
        # Ловим маркер начала блока фичера по нулевому выравниванию слова
        if fd_bytes[cursor] == 0x00 and fd_bytes[cursor+1] == 0x00:
            try:
                # Распаковываем feat_id (uint32) и feat_type (uint16) с динамическим эндианом
                feat_id, feat_type = struct.unpack(f"{endian_mask}IH", fd_bytes[cursor+4:cursor+10])
                if 0 < feat_id < 100000:
                    # Сканируем окно размерных токенов double прямо за заголовком фичера
                    window = fd_bytes[cursor+10:cursor+74]
                    doubles = [struct.unpack(f"{endian_mask}d", d)[0] for d in re.findall(rb'[\x00-\xff]{8}', window)]
                    
                    # Отсекаем бинарный шум выравнивания, оставляя реальные физические размеры КД
                    valid_dimensions = [round(v, 3) for v in doubles if 0.01 < abs(v) < 100000.0]
                    if valid_dimensions:
                        mutations_log.append({
                            "feat_id": int(feat_id),
                            "feat_type_code": feat_type,
                            "nominal_and_backup_values": valid_dimensions
                        })
                    cursor += 24  # Фиксированный шаг структуры фичера в Creo UGC
                    continue
            except Exception:
                pass
        cursor += 1
    return mutations_log
