# ПРАВИЛА ДОМА (rules) — редактор правил

**Класс Р:** правила — это данные, а не действия. Применение правил — отдельная задача
(волна 5, `checks_run`); здесь они только хранятся, проверяются и показываются.

## ЗАЧЕМ
Архитектура правил взята у вендора (`repo\B&W\13_ДВИЖОК_ПРАВИЛ.md`, схема из `rule.xml`):
**правило · цель (объект) · критерий · условие**, соединённые логикой, плюс ссылка
«что применить». У вендора 61 правило и 986 критериев, логика — конъюнкции
(1272 `and` против 23 `or`), значит и наш движок по умолчанию соединяет критерии через И.

## ОКНО
```
rules_gui.bat
```
- **Слева** — правила в порядке файла (порядок важен: первое совпавшее идёт первым в отчёте);
- **Справа** — вкладки: `Текст правил` (IF…THEN…END_IF), `Форма` (список + ▲▼ + Вкл/Выкл + Удалить),
  `О файле` (схема, операции, типы);
- кнопки `Проверить форму` · `Сохранить` · `Показать текстом`.

**Константа 6 волны 1** («правила и текст, и форма») соблюдена: одно и то же правило
читается как JSON (его читает движок) и как текст (его читает человек).

## ОПЕРАЦИИ И КРИТЕРИИ
Операции: `equal`, `unequal`, `bool`, `regexp_match`, `contains`, `less`, `greater`,
`less_equal`, `greater_equal`.
Типы: `parameter`, `param_value`, `item_name`, `group`, `feature`, `feat_type`, `component`.

## ИЗ АГЕНТА
- `rules_list` — сводка: сколько правил, по типам и операциям;
- `rules_text` — правила текстом (`rule_id` — одно правило);
- `rules_check` — прогон по фактам модели; без аргументов — демо-прогон (5 фактов, 4 совпадения).

## ПРАВИЛА ЧЕСТНОСТИ
- `validate()` ловит чужую схему, дубли `id`, неизвестные операции и пустые критерии;
- `save()` **не пишет невалидный файл** — сначала проверка, потом запись;
- битый JSON даёт понятную ошибку, а не исключение.
