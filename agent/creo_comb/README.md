# ЧЕСАЛКА (creo_comb) — JLINK, без CREOSON

**Класс Ж** (живое Creo): причёсывает детали и сборки по ЭТАЛОНУ — шаблонам, прописанным
в `config.pro`. Сейчас готово только **чтение** (пробы и отчёт), запись (`add`) — следующим шагом.

## ОКНО (для рук)
```
creo_comb.bat tpl-plan                      — какие шаблоны прописаны в конфиге и есть ли файлы (без Creo)
creo_comb.bat refs                          — уравнения и параметры ЭТАЛОНОВ (нужен Creo)
creo_comb.bat dump <папка|файл> [имя]        — уравнения+параметры одной модели
creo_comb.bat scan <папка> [config.pro]      — чего не хватает моделям папки против эталонов
```

## ДВИЖОК (для ИИ и скриптов)
`creo_comb.bat <режим> [аргументы]` — все режимы пишут отчёт в консоль (перенаправляется в файл).
Запись в модели — только режим `add` и только с флагом `--apply`.

## РЕЖИМЫ
```
tpl-plan [config.pro]              — шаблоны из конфига: путь, файл, версия (без Creo)
refs                               — уравнения и параметры ЭТАЛОНОВ (нужен Creo)
dump <папка|файл> [имя]            — уравнения+параметры одной модели
scan <папка> [config.pro]          — чего не хватает моделям папки против эталонов (только чтение)
scan-here [config.pro]             — то же по текущей папке сессии (пути без кириллицы в аргументах)
add <папка> [config.pro] [--apply] — ДОБАВИТЬ недостающие параметры и уравнения
probe-open <папка> <имя>           — проба открытия: почему Creo не берёт чертёж
probe-open-f <файл-со-списком>     — то же по списку «<папка>|<имя>» (обход проблем с кириллицей в cmd)
```

## ЧТО ДЕЛАЕТ `add`
1. Читает ЭТАЛОНЫ из `config.pro` (`template_solidpart`, `template_designasm`) — параметры, уравнения,
   уравнения пострегенерации и **ОГРАНИЧЕНИЯ** (перечислимые значения: ТИП, ТИП2, ФОРМАТ,
   РОЛЬ_В_ЛИТЕЙНОЙ_СИСТЕМЕ, материалы).
2. Для каждой модели папки считает **недостающее** (по именам; ничего не заменяет).
3. Без `--apply` — только план. С `--apply` — по каждой модели:
   копия `<папка>\_pre\<дата_время>_<файл>` → создание параметров (значение из эталона, пустое — пустым,
   `ТИП` = Деталь/Сборка по типу модели) → уравнения и пострегенерация ДОПИСЫВАЮТСЯ к существующим →
   регенерация → `Save()`.
4. Итог: `проверено N, к правке M, исправлено K, ошибок E`.

## Правила дома, уже вшитые
* **Эталон — из config.pro**, а не из головы: `template_solidpart`, `template_designasm`,
  `template_sheetmetalpart`. Creo-версии разрешаются: `mm_part.prt` → `mm_part.prt.1`.
* **Читаем оба вида уравнений**: обычные (`GetRelations`) и **пострегенерации**
  (`GetPostRegenerationRelations`) — там живёт `MASS = PRO_MP_MASS`.
* Рабочий каталог сессии сохраняется и возвращается на место; открытые модели убираются из сессии.
* Если живых сессий Creo несколько, JLINK даёт `XToolkitAmbiguous` — правило дома: **одна сессия Creo**.
