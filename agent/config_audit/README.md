# config_audit — проверка путей config.pro (класс Р, без Creo)

## Зачем
Конфиг дома — 385 строк и 56 путей. Если файл/каталог пропал (переименовали, не завезли на новую
машину), Creo не скажет об этом прямо: он просто молча работает без настройки. Программа проверяет
**каждый путь** и говорит, чего нет. Родилась на аудите дома 23.09.2026: нашлись опечатка `.prt1`
и мёртвый `$PROSTD\weld`.

## НАСТРОЙКИ — в одном месте
`D:\AI\tools\agent\data\config_audit_settings.json`:
```json
{"last_config": "...", "creo_vars": {"$PROSTD": "Z:\\PTC\\CREO-START\\НАСТРОЙКИ"}}
```
Выбранный config.pro **переживает перезапуск окна**. Пути к установке Creo здесь **не хранятся** —
их даёт общий поиск (см. следующий раздел), иначе версия протухнет при переезде домена.
Если файл из `last_config` исчез, программа сама берёт первый живой из общего поиска.

## Запуск (консоль)
```
config_audit.bat                    # боевой config.pro (Z:\PTC\CREO-START\START-STD\config.pro)
config_audit.bat <путь\config.pro>  # любой другой (например, локальный CREO-LOCAL-START)
```
**Коды выхода:** `0` — все пути на месте · `1` — есть битые пути · `2` — нечего проверять
(файла нет или он не читается). Планировщик различает эти исходы без разбора вывода.

## Что умеет
- берёт из строки **значение** (отрезает хвостовой комментарий `! …`), понимает `\` и `/`;
- подставляет переменные Creo: `$PRO_DIRECTORY`, `$CREO_COMMON_FILES`, `$PROSTD` — пути берутся
  из настроек, проверяются на существование, и только потом ищутся на диске (см. «НАСТРОЙКИ»);
- учитывает **версии Creo**: `mm_part.prt` → на диске `mm_part.prt.1` — это «есть»;
- пишет **журнал и отчёт** сам (обе руки зовут один `write_report()`), в отчёте видно, какие
  подстановки использованы и есть ли они на диске;
- **сверяет плагины боя с картой** (`audit_protk()`, ЭТАП 9 волны 10, 03.10.2026): читает
  строки `protkdat` из config.pro, включая закомментированные `!protkdat`, и сверяет их с
  картой `..\dev\PLUGINS.md` (раздел «ЖИВАЯ ПРОВЕРКА», строки вида `- protkdat <путь>`).
  Расхождения трёх видов: `нет_в_карте` (**провал** — новый плагин в бою не зафиксирован),
  `нет_на_диске` (**провал** для активной строки — файл `protk.dat` отсутствует),
  `нет_в_бою` (предупреждение — карта обещает модуль, которого в config.pro нет, обычно
  «модуль сняли»). Блок печатается и в CLI, и учитывается в коде выхода; в общем прогоне
  дома это проверка `plugins_registry` (`python checks.py`). Приёмка: `python dev\vol9_check.py`.
  **Живой находка 03.10.2026:** `!protkdat` не читался вовсе (знак `!` снимался только у
  незакомментированных строк) — KeyShot не попадал в разбор и рождал ложное «нет_в_бою».

## Границы
- проверяет **файлы**, а не смысл настройки: «файл есть» ≠ «настройка верна»;
- пути внутри файлов (например, содержимое `search.pro`) не проверяются — это работа `orphan_scan`;
- если путь содержит пробелы — берётся вся строка целиком (проверено на
  `protkdat D:\CGTech\VERICUT 9.0.1\...\protk.dat`);
- **третьей руки (визард витрины) нет** — CLI и окно.
