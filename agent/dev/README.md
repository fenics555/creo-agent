## ПЕСОЧНИЦА (полные проверки без риска для дома)
Обе проверки умеют работать на копии дома — **правки проверяются на песочнице, боевые пути не трогаются**:
```
python dev\skills_check.py D:\AI\PROBA\skills_test     # проверка скиллов на копии репо
python dev\culture_check.py D:\AI\PROBA\kultura_test    # все 10 разделов культуры на копии дома
```
В песочнице меняется ВСЁ, включая запись: эталон и отчёт создаются **внутри песочницы**
(`baseline.txt`, `skills_check_report.txt`), а не в боевых путях. Без аргумента — боевой дом.

**Правило пробы (03.10.2026):** макет песочницы собирает САМ скрипт и обязан создать ВСЕ
каталоги, иначе проверка молча пропустит разделы и «зелёный» результат ничего не значит.
Обязательные сценарии: **чистый макет → RC=0** и **ломаный макет (все нарушения разом) → RC=1**.
Готовая проба: `D:\AI\data\tmp\probe_skills_sandbox_20261003.py`, `probe_culture_sandbox_20261003.py`.

**С чего начать новой ноге:** `skills_check.py` (шапки скиллов) → `culture_check.py` (гигиена файлов) →
`ui_check.py` (если правил витрину). Читай **первые 15 строк** файла, а не запускай его: в папке
есть правящие скрипты (см. `doctor.py`).

**Правило (карта дома — `D:\AI\repo\CULTURE_files.md`):**
- **вывод пробы пишем в урну**: `D:\AI\log\urn\cline\<тема>\…` — не в `log\reports` (там только отчёты
  `REPORT_<задача>_<исполнитель>_<дата>.md`) и не в корень `D:\AI` (там ему делать нечего);
- временные скрипты-писатели и патчи — тоже урна: `D:\AI\log\urn\cline\`;
- уборка — `log_clean` по срокам из `D:\AI\log\retention.json` (урна 14 дней, отчёты 28, логи программ 30–56);
- копия файла перед правкой — `..\data\backup\pre_<метка>_<файл>` (не чистится: это откат).

**Правило:** эталон (`skills_check_baseline.txt`) обновляют **только после разбора** текущих нарушений —
иначе «мусор» станет нормой. Окно об этом спрашивает отдельным вопросом.
