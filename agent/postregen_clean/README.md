# POSTREGEN_CLEAN — ОЧИСТКА ПОСТ-РЕГЕНЕРАЦИИ, ПАРАМЕТРОВ И ПЕРЕИМЕНОВАНИЕ ВИДОВ

Отдельная программа со своим окном и своими настройками. Три действия, каждое
выключается отдельно: **очистить уравнения пост-регенерации**, **удалить
параметры по маскам**, **переименовать виды (элементы модели)**.

## ГЛАВНОЕ: СНАЧАЛА ПРОВЕРИТЬ, ПОТОМ ЧИСТИТЬ
1. **ПРОВЕРИТЬ** строит план и **НИЧЕГО НЕ ПИШЕТ**. Уравнения пост-регенерации
   лежат внутри модели, поэтому план читается через CREOSON (живую модель).
2. **ОЧИСТИТЬ** пишет в Creo **только после галочки согласия** и только по
   проверенному плану, и только после второго подтверждения о том, что запись
   необратима.
3. **СТОП** останавливает цикл между моделями; отчёт говорит, где остановились.

## ЗАПУСК ОКНА (без агента и без Cline)
`postregen_clean_gui.bat` — двойной щелчок, окно открывается само.
Настройки живут файлом `agent\data\postregen_clean_settings.json` и переживают
перезапуск окна.

## НАСТРОЙКИ ОКНА (таблица справа, значение правится двойным щелчком)
| Настройка | Смысл |
|---|---|
| root | папка с моделями; пробы — только `D:\AI\PROBA`, на `Z:` только чтение |
| mask | маска файлов: `*.asm` или `*.prt` |
| only | только эти имена через `;` (пусто = все) |
| postregen | очистить уравнения пост-регенерации: да/нет |
| param_masks | удалить параметры по маскам через `;` (пусто = не удалять) |
| rename_map | переименовать виды `СТАРОЕ=НОВОЕ` через `;` (пусто = не переименовывать) |
| limit | сколько моделей просмотреть |
| approve | **СОГЛАСИЕ на запись**: нет/да. Без «да» кнопка ОЧИСТИТЬ откажет (RC 3) |
| dry_run | проба без записи: да/нет |

## ЧТО ИМЕННО ПИШЕТ ПРОГРАММА (живые спеки CREOSON jsonSpecs)
| Действие | Вызов CREOSON |
|---|---|
| очистить уравнения пост-регенерации | `file:postregen_relations_set {file, relations: []}` |
| удалить параметры по маске | `parameter:delete {file, name: маска}` |
| переименовать элемент модели | `feature:rename {file, name, new_name}` |
| пересчёт и сохранение | `file:refresh`, `file:save` |

Пустой список `relations` — это очистка: в живой спеке
`file-postregen_relations_set.json` сказано «Clear the relations if missing».

## ЩИТЫ (почему запись не уйдёт не туда)
1. **Согласие**: без `approve` запись не начинается (RC 3).
2. **Щит активной модели**: перед записью сверяется, что в Creo активна ИМЕННО
   целевая модель — по полному пути, а не по имени (инцидент 03.10.2026, когда
   стен боевой и копии одинаков и параметр ушёл в боевую модель).
3. **Честный отказ**: нет CREOSON или нет Creo — RC 2 «запись НЕ выполнена»,
   а не «прогон успешен».
4. **Z: не трогаем**: программа не пишет на сетевой склад и не правит `config.pro`.

## RC (коды возврата)
| Код | Значит |
|---|---|
| 0 | применено (или проба `--dry_run`) |
| 1 | часть шагов не вышла — смотри отчёт |
| 2 | нет CREOSON/Creo или нечего делать — записи не было |
| 3 | нет согласия — запись не начиналась |
| 4 | щит: активна другая модель или модель не открылась |

## КЛИ (без окна)
- `plan.bat "папка" --mask=*.asm` — план, записей нет.
- `apply.bat plan.json --approve` — запись; без `--approve` отказ RC 3.

## ГРАБЛИ (учтены в коде)
1. Уравнения пост-регенерации читаются **только у открытой модели** — иначе
   «File ... was not open». План тоже открывает модель, но только на чтение.
2. `display:false` **не даёт активного окна**: модель открывается, но активной
   модели нет, и запись прервалась бы щитом. Нужен `activate` БЕЗ `display:false`.
3. В окне журнал создаётся **до** таблицы настроек: таблица пишет в журнал
   при создании.

## ЧЕГО НЕ ДЕЛАЕТ
- Не трогает виды на чертеже: для этого другая функция `drawing:rename_view`
  (в этой программе переименуются элементы модели `feature:rename`).
- Не удаляет параметры при пустой маске — пусто значит «не удалять».
- Не пишет на `Z:` и не поднимает CREOSON сам.
