# PLAN_RUN — ПЛАНЫ ЗАДАЧ `plan.json` → ИСПОЛНЕНИЕ ПО ШАГАМ (класс Ж, волна 8, V1)

**Этап 6 плана.** До сих пор планы живут внутри инструментов. Теперь есть **один формат**
и **исполнение плана по кнопке** с журналом шагов.

## С чего начать новой ноге
1. Прогнать приёмку: `python -X utf8 dev\vol8_check.py` (из `D:\AI\tools\agent`).
2. Регресс: `python -X utf8 checks.py`, `dev\win_check.py`, `dev\skills_check.py`.
3. План строит `batch_params\plan.py`; перевод в единый вид — `plan_fmt.from_batch_params`.

## ФОРМАТ ОДНОГО ШАГА
| Поле | Что значит |
|---|---|
| `n` | номер шага, сквозной |
| `what` | ЧТО делаем (имя операции, напр. `set_param`) |
| `where` | ГДЕ — **полный путь** цели |
| `args` | аргументы операции |
| `risk` | РИСК: `read` (не пишет) · `write` (пишет) · `destructive` |
| `rollback` | КАК ОТКАТИТЬ — **обязателен** |
| `verdict` | что показала разведка: `change` / `same` / `miss` / `read_fail` |

Закон: `plan_version` = 1; шаг без `what`, `where`, понятного `risk` и `rollback` —
**битый план**, он не исполняется, а отвергается с перечислением ошибок.

| Риск | Что делает | Как проверяется |
|---|---|---|
| `read` | не пишет | идёт в журнал |
| `write` | пишет | **по файлу на диске** |
| `destructive` | разрушает | по файлу на диске |

Исполнитель знает операции, а не инструменты: `set_param`, `rename_model`.
Каждая ветка зовёт доказанный путь дома. Неизвестная операция — честный отказ.

## ГЛАВНОЕ ПРАВИЛО КЛАССА Ж
1. **План — отдельно, исполнение — отдельно.** План читается и проверяется **без Creo**.
2. **Согласие обязательно**: без `approve=1` — RC 3, шаги не начались.
3. **СТОП проверяется первым**, до цикла: нажат до начала — не начинаем вообще.
4. **Щит «только копия»**: активная модель сверяется **по полному пути** (инцидент
   `din439`, 03.10.2026). Не совпало — RC 4 и стоп.
5. **Нет CREOSON — честный отказ RC 2**, а не «прогон успешен».

## ТРИ РУКИ
| Рука | Запуск | Что делает |
|---|---|---|
| CLI | `plan_run\run.bat <plan.json> [--approve] [--dry_run]` | исполняет план, журнал, отчёт |
| Окно | `plan_run\plan_run_gui.bat` | список шагов, риск, ВЫПОЛНИТЬ, СТОП, журнал |
| Агент | `plan_build`, `plan_run`, `plan_report` | то же |
| Разбор | `plan_run\plan_fmt.py <plan.json>` | показать и проверить план |

## RC
| Код | Значит |
|---|---|
| 0 | выполнено (или проба `--dry_run`) |
| 1 | часть шагов не вышла — смотри отчёт |
| 2 | нет CREOSON или план не прошёл проверку |
| 3 | нет согласия — шаги не начались |
| 4 | щит: активна не та модель |

## ГДЕ ПИШЕТ

- Отчёты: `D:\AI\log\reports\REPORT_plan_run_*.md`.
- Файлы планов: `D:\AI\log\plans\plan_*.json`.

## КОНТРАКТЫ CREOSON, доказанные живой записью 03.10.2026 (волна 8)
1. **`parameter:set` не берёт стем без расширения** — дословно `Error: Invalid File Name`.
   Берёт имя с расширением **или полный путь**. Раньше код передавал стем.
2. **`parameter:set` меняет только сессию.** Без `file:save` на диске ничего нет.
   Сохранение встроено в шаг (поле `save`, по умолчанию да).
3. **`rename_tools` работает в рабочей папке Creo и принимает ТОЛЬКО имя**, не путь.
   С абсолютным путём отвечает `новое имя: латиница/цифры/_-`.
4. **Успех rename проверяется по диску, а не по тексту ответа:** его отказ не
   содержит слов «ошибка», и фильтр по словам давал ложный успех (RC 0 без файла).

## ЧЕГО НЕ ДЕЛАЕТ
- Не выдумывает свой вызов CREOSON: запись идёт доказанным путём `batch_params\apply`.
- Не трогает витрину (`app.js`, `http_handlers.py`).
- Не поднимает Creo сам: мёртвый стек — это отказ с кодом.
