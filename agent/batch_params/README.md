# BATCH_PARAMS — ПАКЕТНЫЕ ПАРАМЕТРЫ И ПЕРЕИМЕНОВАНИЕ ПРИЗНАКОВ (класс Ж, волна 7)

**Этап 5 плана.** `creo_batch_params` + `feature_rename` — с планом, согласием и СТОП.

## ГЛАВНОЕ ПРАВИЛО КЛАССА Ж
1. **План — отдельно, запись — отдельно.** План строится чтением файлов (`creo_read`),
   **Creo не нужен**. Человек видит план ДО записи.
2. **Запись только по согласию**: без `approve=1` / галочки «да» — RC 3, запись не началась.
3. **Нет CREOSON — честный отказ RC 2**, а не «прогон успешен».
4. **СТОП** останавливает цикл между моделями; отчёт говорит, где остановились.
5. **Боевой `config.pro` не правим никогда.** Запись идёт через доказанный `set_param`.

## ТРИ РУКИ
| Рука | Запуск | Что делает |
|---|---|---|
| CLI план | `batch_params\plan.bat <папка> --param=ИМЯ=ЗНАЧ` | строит план, отчёт + JSON, записи НЕТ |
| CLI запись | `batch_params\apply.bat <plan.json> [--approve] [--dry_run]` | исполняет план |
| Окно | `batch_params\batch_params_gui.bat` | план, галочка согласия, ПРИМЕНИТЬ, СТОП |
| Агент | `batch_params_plan`, `batch_params_apply`, `feature_rename_plan` | то же |

## RC
| Код | Значит |
|---|---|
| 0 | применено (или проба `--dry_run`) |
| 1 | часть шагов не вышла — смотри отчёт |
| 2 | CREOSON не отвечает ИЛИ нечего делать — записи не было |
| 3 | нет согласия — запись не начиналась |
