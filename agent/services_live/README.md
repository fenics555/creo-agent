# services_live V1 — живая проверка стека (класс Р, только чтение)

## Зачем
`checks.py` проверяет **файлы** — поэтому «16/16 зелёно» не видит, что агент лежит. Этот
инструмент смотрит **живые службы**: слушает ли порт, отвечает ли `/health`, совпадает ли
`agent.pid` с живым процессом. Образец — `ctl.py status()` (`alive(port)` + `verify_agent`).

## Что делает
1. Для каждой службы из настроек: порт слушает (`socket`), при наличии `health` — HTTP-ответ
   (`/health` даёт 200 или 401 — оба значат «жив и проверяет вход»).
2. Приёмка агента: порт 8765 держит процесс, чей PID = `agent.pid` (как `verify_agent`).
3. Вердикт: **СТЕК ЖИВ** / **СТЕК НЕ ПОЛНОСТЬЮ ЖИВ**. Обязательна только служба с `required:true`.

## ОКНО / КОНСОЛЬ
```
python services_live.py          # человекочитаемо
python services_live.py --json   # машиночитаемо (для встраивания в checks.py)
```
Код возврата: **0** — все обязательные живы · **1** — что-то обязательное мертво.

## Границы
- **Только чтение:** ничего не поднимает, не останавливает, не пишет.
- Порты/службы — из настроек (`settings\settings.json`), абс. путей в коде нет (канон №2).
- Не дублирует `ctl.py`: тот управляет, этот — измеряет и пригоден для каркаса проверок.
